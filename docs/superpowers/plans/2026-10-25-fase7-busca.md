# GestorCC — Fase 7: Busca inteligente — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A barra de busca passa a interpretar perguntas com o Gemini, no nível gratuito, sem enviar dados do sistema (spec 10.3).

**Architecture:**
- **O que o Gemini recebe:** a ação `busca.interpretar` envia **só a pergunta**, junto com:
  - a lista de consultas, como declarações de função;
  - o manual de uso `docs/manual/uso.md`, que não tem dados reais;
  - a data de hoje.
- **O que ele devolve:**
  - uma `Consulta`, que é a chamada de função validada; ou
  - uma resposta de ajuda, para perguntas sobre como usar o sistema.
- **Onde a consulta roda:** no app, pelas ações que já existem, com o token de quem perguntou. Assim valem as permissões dessa pessoa.
- **Limite e falhas:** há um limite diário por pessoa (`config.limitePerguntasDia`). Sem chave, com o limite atingido ou com o Gemini fora do ar, o app usa a interpretação por palavras-chave do protótipo. Se nem ela entender, mostra "Não consegui interpretar agora; veja os resultados da busca".

**Spec:** `docs/superpowers/specs/2026-10-24-gestorcc-design.md`, seção 10.3.

## Global Constraints

- **Os dados do sistema nunca vão para o Gemini.** O teste confere que o corpo enviado não tem nenhum dado das planilhas.
- **Sem marca de "IA" na interface.** As respostas trazem "resposta automática · confira os dados".
- **Custo zero:** só o nível gratuito.
  - A chave fica na propriedade `GEMINI_API_KEY`.
  - O modelo vem de `GEMINI_MODELO`, padrão `gemini-2.5-flash`.
- **Permissão:** `busca: ver`. `VITE_RECURSOS` da fase 7 = o da fase 6 + `busca`.

## Review Focus

1. **O Gemini devolve uma função que não existe, ou parâmetros errados** (data em outro formato, termo vazio). Vira `consulta: null`, e o app cai na interpretação local. → teste na Task 1.
2. **Limite diário atingido.** Volta `motivo: 'limite'` sem chamar o Gemini. → teste na Task 1.
3. **Gemini fora do ar ou com cota esgotada (HTTP 429).** Volta `motivo: 'indisponivel'`, sem erro para a pessoa. → teste na Task 1.
4. **Pergunta muito longa.** É cortada em 500 caracteres antes do envio. → teste na Task 1.
5. **Pergunta de uso** ("como troco minha senha?"). A resposta de ajuda aparece no card. → teste na Task 2.

### Task 1: `busca.interpretar` na API

- **Tipo:** `Consulta` vai de `app/src/busca/interpretarSimulado.ts` para `shared/src/busca.ts`, e o app passa a importá-la de lá.
- **Contrato:** `'busca.interpretar': A<{ pergunta: string }, { consulta: Consulta | null; ajuda: string | null; motivo: 'limite' | 'indisponivel' | null }>`.
- **Porta:** `ia: { gerar(corpo: object): unknown | null }`.
  - Devolve `null` quando não há chave.
  - Lança erro se o Gemini falhar.
  - No Apps Script, usa `UrlFetchApp` com `muteHttpExceptions`; resposta diferente de 200 vira erro.
- **Funções puras** (`api/src/busca/gemini.ts`):
  - `montarPedido(pergunta: string, hoje: DataISO, manual: string): object`;
  - `lerResposta(r: unknown): { consulta: Consulta | null; ajuda: string | null }`.
- **Manual:** `docs/manual/uso.md`, importado como texto. No build, entra por um plugin do esbuild para `*.md?raw`; nos testes, o Vitest já entende `?raw`.
- **Limite:** um contador por pessoa e dia no cache, com a chave `busca:<pessoaId>:<AAAA-MM-DD>`.

**Testes** (`api/test/busca.test.ts`):
- o pedido leva a pergunta (cortada em 500 caracteres), as funções e o manual, e nenhum dado das planilhas;
- `functionCall` `escalaDoDia` com `{ data: '2026-12-05' }` vira a consulta;
- função desconhecida ou data inválida → `null`;
- texto → `ajuda`;
- sem chave → `motivo: 'indisponivel'`;
- limite 2 → a terceira pergunta tem `motivo: 'limite'` e não chama a porta;
- erro da porta → `'indisponivel'`.

### Task 2: App da fase 7 e publicação

- **Busca:** `Busca.perguntar` chama `busca.interpretar`.
  - Com `consulta`, executa `executarConsulta`.
  - Com `ajuda`, mostra o texto no card.
  - Sem nenhum dos dois, tenta `interpretarSimulado`; se ele também não entender, mostra a mensagem de "não consegui interpretar".
- **Simulador:** no protótipo, `busca.interpretar` responde com `interpretarSimulado`.
- **Testes** (`app/src/layout/Busca.test.tsx`):
  - uma consulta vinda da API mostra o card;
  - uma ajuda mostra o texto;
  - `indisponivel` cai na interpretação local.
- **Publicação:** versão `0.7.0`, `.env` e seção 18 do guia, explicando como criar a chave grátis no Google AI Studio e colar em `GEMINI_API_KEY`.
